IMPLEMENTATION
Replaced only the activity selector's flat list with WPF TreeView. New pure
activity_tree.py constructs WBS hierarchy and child activities from normalized
IDs, preserving source sibling order. UI carries the original Activity key,
never a label or WBS key. Expand/collapse and hierarchy-aware search work with
Thai/English strings. Selection is set through TreeViewItem.IsSelected;
TreeView.SelectedItem is read-only. Headings clear the mapping target. A search
that hides the selected Activity clears its target; collapse retains the target
with explicit details. Normal expansion survives refresh; search expands
matching context transiently. Tree state is not persisted.

Defensive tree construction retains orphan/missing/duplicate WBS identities
and cycles with visible warnings. Invalid Activity keys are nonassignable.
This is a projection, not silent data repair: strict existing P6 import and work
validation remain unchanged and may reject malformed schedules before viewing.
No activities are silently discarded by the projection. The public synthetic
fixture and pure tests exercise these cases without claiming broader P6 support.

PRESERVED BEHAVIOR
Many-to-many Add, duplicate no-op, independent Reassign/Remove, note editing,
Undo, review/native selection, Import/Open/Save, validation and exchange remain
on existing domain commands. Core, importer, storage and native adapter are
unchanged. Existing valid working files need no migration. Source model guards,
missing-element handling and renderer-independent exchange retain baseline rules.
